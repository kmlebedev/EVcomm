# ГИС ЖКХ: документация и план интеграции учёта зарядки электромобилей

Дата проверки: 25 сентября 2026 года. Сценарий: передать потребление электроэнергии для последующего начисления по лицевому счёту жителя УК «Академический», Екатеринбург.

## 1. Где находится официальная документация

Основной источник — [каталог «Взаимодействие с внешними системами»](https://my.dom.gosuslugi.ru/#!/regulations?rubricNames=%D0%92%D0%B7%D0%B0%D0%B8%D0%BC%D0%BE%D0%B4%D0%B5%D0%B9%D1%81%D1%82%D0%B2%D0%B8%D0%B5%20%D1%81%20%D0%B2%D0%BD%D0%B5%D1%88%D0%BD%D0%B8%D0%BC%D0%B8%20%D1%81%D0%B8%D1%81%D1%82%D0%B5%D0%BC%D0%B0%D0%BC%D0%B8). Ссылку на него содержит [официальная страница документации](https://cdn.dom.gosuslugi.ru/webhelp/new/topics/introduction/c_documentation-aoss.html).

Искать архив с названием «Регламент и форматы информационного взаимодействия внешних информационных систем с ГИС ЖКХ». Если прямой переход не работает: портал ГИС ЖКХ → «Регламенты и инструкции» → «Взаимодействие с внешними системами».

Для разработки нужны:

| Документ или файл | Для чего нужен |
|---|---|
| Регламент взаимодействия | Порядок подключения и организации обмена |
| Альбом ТФФ — транспортных форматов файлов | Структуры сообщений, сценарии, ограничения, ошибки |
| WSDL | Контракты SOAP-сервисов, операции и адреса |
| XSD | Схемы XML, обязательные поля и допустимые значения |
| Описание изменений | Проверка совместимости конкретной версии |
| Сопоставление методов и видов информации, если выделено отдельным документом | Определение необходимых прав |

Это перечень для проверки при получении актуального комплекта, а не опись скачанного архива. Наличие WSDL/XSD и Альбома ТФФ подтверждается также [историческим официальным регламентом, версия 5](https://minstroy19.ru/assets/files/docs/dgn/reglament_informatsionnogo_vzaimodeystviya_vneshnih_informatsionnih_sistem_s_gis_zhkh.pdf); его старые требования к подключению и криптографии нельзя использовать как актуальные.

По [объявлению канала интеграции](https://t.me/dom_gosuslugi_integration/539), в промышленной среде установлена версия **16.9.0.0**, опубликованы соответствующие текущие форматы. Текст сообщения доступен в [публичной ленте канала](https://t.me/s/dom_gosuslugi_integration). В каталоге следует выбирать текущий комплект, проверяя его версию и дату.

## 2. Как устроено подключение

Государственный интерфейс использует **SOAP**, что прямо указано в [руководстве оператора информационной системы](https://cdn.dom.gosuslugi.ru/webhelp/new/topics/omnibus/c_operator_is-operator_is.html). Запросы следует строить по официальным XML-схемам и контрактам. Публичный REST/JSON-интерфейс для нашего сценария в официальной документации не обнаружен.

Практический порядок:

1. Определить организацию — оператора интегрируемой ИС и зарегистрировать её в ГИС ЖКХ.
2. Подать заявку на новую ИС, указать сведения о системе, территорию и нужные виды информации.
3. Загрузить квалифицированный сертификат ключа проверки электронной подписи ИС; инструкция допускает `cer`, `der`, `pem`.
4. Подписать и отправить заявку, дождаться её принятия.
5. Получить от УК права на соответствующие данные.
6. Настроить обмен по актуальному комплекту документации, проверить сценарий на стенде, затем выполнять промышленный обмен.

Шаги регистрации описаны в [инструкции по заявке на новую ИС](https://cdn.dom.gosuslugi.ru/webhelp/new/topics/administration/information_systems/add_new_own_is_request-operator_is.html). Там же предусмотрена заявка на доступ к стенду интеграционного тестирования — СИТ. Для коммерческих ИС тестирование названо необязательным; для региональных и муниципальных — обязательным. Для проекта зарядки тестовый прогон рекомендуется как инженерная проверка.

Для УК есть отдельная [инструкция по предоставлению доступа оператору ИС](https://cdn.dom.gosuslugi.ru/webhelp/new/topics/administration/grant_access/grant_is_operator-uo.html). УК выбирает оператора, зарегистрированную ИС, срок и виды информации; оператор принимает заявку. Регистрация системы сама по себе не предоставляет доступ к данным УК «Академический».

Продление или замена сертификата рассматривается в [инструкции по отправке сертификата](https://cdn.dom.gosuslugi.ru/webhelp/new/topics/administration/information_systems/send_check_key_certificate-operator_is.html). Актуальные требования к защищённому соединению и подписанию сообщений нужно брать из текущего регламента: просмотренные инструкции личного кабинета не заменяют технический контракт.

## 3. Какие операции искать для зарядки

Ниже приведены названия из опубликованного [официального регламента версии 5, страницы 14–15](https://minstroy19.ru/assets/files/docs/dgn/reglament_informatsionnogo_vzaimodeystviya_vneshnih_informatsionnih_sistem_s_gis_zhkh.pdf). Это ориентиры для поиска в актуальном WSDL, а не подтверждение сигнатур версии 16.9.

| Объект | Операции для поиска |
|---|---|
| Лицевые счета | `exportAccountData`, `importAccountData` |
| Приборы учёта | `exportMeteringDeviceData`, `importMeteringDeviceData` |
| Показания | `importMeteringDeviceValues` |
| История показаний | `exportMeteringDeviceHistory` |
| Платёжные документы | `importPaymentDocumentData`, `exportPaymentDocumentData` |

Слова import/export здесь указывают направление относительно ГИС ЖКХ. Не следует создавать новые лицевые счета или приборы, если нужные объекты уже заведены УК: сначала требуется сопоставление существующих объектов.

Для асинхронных операций получение подтверждения приёма запроса ещё не означает успешного размещения данных. Нужны получение результата обработки и проверка ошибок по отдельным объектам. Этот принцип описан в разделе 3 [регламента](https://minstroy19.ru/assets/files/docs/dgn/reglament_informatsionnogo_vzaimodeystviya_vneshnih_informatsionnih_sistem_s_gis_zhkh.pdf); конкретные сообщения и интервалы опроса необходимо сверить с текущим Альбомом ТФФ.

## 4. Адреса и тестирование

В [сообщении об ограничениях запросов](https://t.me/dom_gosuslugi_integration/535) названы `https://api.dom.gosuslugi.ru` как работающий адрес и `https://api-gost.dom.gosuslugi.ru` как новый адрес для проверки ограничений частоты HTTP-запросов. Второй адрес нельзя на этом основании считать обычной песочницей. Точные адреса сервисов брать из актуального WSDL; условия доступа к СИТ — из одобренной заявки.

Для клиента рекомендуется очередь отправки, сохранение идентификаторов запросов, повторная проверка результата после сетевого сбоя и защита от повторного начисления. Предел частоты запросов нельзя фиксировать по старым объявлениям: нужен действующий порядок взаимодействия.

## 5. Применение к общей зарядной станции

За месяц учитывается **энергия в кВт·ч**, а не мощность в кВт.

Возможны два разных сценария, выбор которых нужно согласовать с УК:

- **Показания реального прибора учёта.** Если для принятой схемы расчётов прибор зарегистрирован и связан с нужными объектами, исследовать передачу показаний. Месячный расход и накопленное показание счётчика — разные величины; формат нельзя выбирать произвольно.
- **Распределение сессий общей станции между жителями.** Сервер зарядки считает энергию каждого пользователя за месяц, связывает её с лицевым счётом и передаёт УК основание для начисления. Затем уполномоченная система размещает согласованный платёжный документ. Возможность и способ включения услуги зарядки в такой документ ещё требуют проверки; отдельный подтверждённый метод «начислить зарядку электромобиля» не найден.

Моя рекомендация для общей станции — второй сценарий. Показание общего счётчика не описывает распределение энергии между квартирами. Во внутреннем реестре проекта стоит сохранять период, лицевой счёт, кВт·ч по тарифным зонам при необходимости, ссылки на сессии, версию расчёта и статус передачи. Это предложение к нашей модели данных, **не схема запроса ГИС ЖКХ**.

Для пилота критерий успеха должен включать не только принятие запроса ГИС ЖКХ, но и появление корректного начисления в расчётной системе УК и квитанции жителя. Публичных подтверждений того, что УК «Академический» забирает внешние показания из ГИС ЖКХ и автоматически начисляет по ним оплату зарядки, не найдено.

## 6. Вариант через посредника

[Документация API РосКвартала](https://api.roskvartal.ru/) описывает REST-интерфейс посредника, в том числе операции с показаниями. Это отдельный сервис, а не официальный REST API ГИС ЖКХ. На просмотренной странице указана версия форматов 16.5.0.0; поддержку актуальной версии и нужных операций следует подтвердить у поставщика перед выбором решения.

## 7. Что осталось неподтверждённым

Точный адрес официального каталога и инструкции найдены. Текущий архив 16.9 скачать и проверить не удалось: портал каталога оказался недоступен инструментам, а браузерная проверка безопасности не позволила открыть его. Поэтому здесь нет утверждений о проверенных полях XML, актуальных сигнатурах методов или успешном выполнении запросов. Тестовые и промышленные вызовы не выполнялись.

Для следующего технического этапа нужны текущий комплект WSDL/XSD/ТФФ, выбранный вместе с УК сценарий начисления и соответствующие права. После этого можно составить точное сопоставление полей и проверить одну передачу от сессии зарядки до квитанции.
