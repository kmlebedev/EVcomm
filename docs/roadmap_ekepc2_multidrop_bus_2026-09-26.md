# EVcomm: связь с несколькими EKEPC2-S на шине WB-MGE v.3

Версия 0.4 · 26 сентября 2026

Статус: проверка архитектуры [roadmap_type2_evse_controller_2026-09-26.md](roadmap_type2_evse_controller_2026-09-26.md) (дальше — «исходный документ») по первоисточникам и коду репозитория, дорожная карта модуля связи. Всё, что помечено «стенд», — гипотеза до измерения на конкретной прошивке EKEPC2.

**Принятые решения (26.09.2026):**

1. **По одному EKEPC2 на однофазную линию L1–L3**, N = 3 на пост. Нагрузка — однофазные EV Geely и BYD. Линия 3P (K4) в объём модуля не входит.
2. **Вариант B принят при технической возможности.** EKEPC2 ставятся на RS485-2 вместе со счётчиками, MR6C остаётся один на RS485-1. Условия возможности — раздел 4.1. WB-MAP12E работает по Modbus RTU, поэтому условию по протоколу он удовлетворяет.
3. **Потеря связи с EKEPC2 во время заряда → MR6C OFF** через `evse_lost_grace` = 3 с. Kx разрывает и фазу, и нейтраль. Новые ON запрещены до восстановления связи и полной сверки.
4. **На линии два разъёма** (раздел 5.10):
   - основной — GB/T от штатного wallbox Geely или BYD: током не управляем, EVcomm только подаёт и снимает питание;
   - вспомогательный — Type 2 с EKEPC2: ток управляем через CP.

   Если на GB/T заряжается машина, которая берёт не весь ток линии (гибрид, 16 А), Type 2 может работать одновременно с остатком тока. Если Type 2 начал зарядку первым, GB/T **на этой же линии** недоступен до конца сессии Type 2. Другие линии поста не блокируются.
5. **GB/T и Type 2 одной линии могут одновременно заряжать машины разных лицевых счетов.** Учёт — по ветке (вариант U2). Вместо шести однофазных счётчиков ставится один многоканальный WB-MAP12E на пост:
   - канал 1 — ветки GB/T линий L1–L3;
   - канал 2 — ветки Type 2.

   WB-MAP12E внесён в Госреестр СИ (79082-20). Производитель при этом позиционирует его для технологического учёта, поэтому применение для расчётов с жильцами должен подтвердить метролог (раздел 5.10).

## 1. Итог

1. **Каркас исходного документа верен.** EKEPC2 только slave, уникальные адреса, DLB и опрос внешних счётчиков выключены, у шины один владелец, мульти-unit симулятор, питание Type 2 только при двух разрешениях (MR6C и EKEPC2). Эти пункты подтверждаются документацией ETEK, Wiren Board и исходниками `simonvetter/modbus`.
2. **Четыре места нужно исправить** (раздел 2):
   - контроль по регистру 152 до подключения EV;
   - штатная остановка снятием разрешения MR6C под нагрузкой;
   - `EVSEState` как прямое отображение CP;
   - механизм общей шины через mutex.

   Не учтено, что текущий автомат линии ([post.go](../internal/controller/post.go)) переведёт в `FAULT` каждую нормальную Type 2 сессию.
3. **Найдены факты, которых нет в исходной архитектуре** (раздел 3):
   - WB-MGE не пересылает Unit ID 255 на шину, а это заводской адрес EKEPC2;
   - R/W-регистры EKEPC2 энергонезависимы, частая запись регистра 109 изнашивает память;
   - скорость EKEPC2 фиксирована прошивкой (38 400 в мануале 2022, 9600 в инструкции 2026);
   - карта состояний регистра 141 зависит от прошивки;
   - EKEPC2 сам возобновляет зарядку после RCMU-fault;
   - таблица PP-резисторов в мануале 2022 не совпадает с IEC 61851-1.
4. **Главная рекомендация (принята) — не переносить EKEPC2 на шину MR6C.** MR6C остаётся один на RS485-1: 115 200, опрос 100 мс, как сейчас. Три EKEPC2 ставятся на RS485-2 вместе со счётчиками поста: «Меркурий 234» и WB-MAP12E. Порт работает прозрачным мостом 9600 8N1, Go на нём — единственный мастер. Все счётчики на этом порту должны работать по протоколу с однобайтовым адресом, «Меркурий 200» исключён (раздел 4.1). Что это даёт:
   - watchdog MR6C не зависит от чужих кадров конструктивно;
   - шина MR6C не замедляется в 12 раз;
   - аварийный OFF не ждёт транзакций EKEPC2;
   - второй шлюз не нужен.

   Цена — свой Modbus RTU-кодек поверх [internal/rtu](../internal/rtu/conn.go), общий исполнитель порта для счётчиков и EKEPC2 и пересмотр правила 13 раздела 5 [discovery-документа](hardware_discovery_provisioning_architecture_2026-09-25.md). Общий исполнитель RS485-2 нужен и без EKEPC2: этап 2 [базовой дорожной карты](roadmap_evse_line_control_go_2026-09-25.md) требует адаптер для нескольких счётчиков на одной шине (R1). Одна работа закрывает обе задачи. Вариант исходного документа (всё на RS485-1 при 9600) остаётся запасным.
5. **Модуль связи** (раздел 5):
   - один исполнитель на физический порт;
   - типизированные операции, без широковещательного адреса;
   - классы приоритета;
   - circuit breaker на каждое устройство;
   - классификация отказов «устройство / шина / шлюз»;
   - только абсолютные, то есть идемпотентные, записи с контрольным чтением;
   - бюджет записей в энергонезависимую память.
6. **Дорожная карта** M0–M8 (раздел 6): около 8–10 недель одного разработчика до пилота. Критический путь — стендовые этапы M1 и M4.
7. **Два разъёма на линии меняют состав поста** (раздел 5.10):
   - два контактора на линию: Kg для GB/T и Kt для Type 2;
   - все шесть выходов MR6C заняты (K1–K3 — GB/T, K4–K6 — Type 2), поэтому режим `1x3` и линия 3P на таком посту недоступны;
   - ток Type 2 при совместной работе ограничивается остатком от лимита линии: в MVP — фиксированным лимитом с программным надзором, позже — локальным DLB EKEPC2 от трансформатора тока линии (без трафика на шине);
   - две одновременные сессии разных лицевых счетов учитываются по своей ветке: WB-MAP12E, канал на ветку. Счётчики линий не нужны, на RS485-2 пять устройств вместо семи;
   - параметры ТТ и привязка фаз WB-MAP12E записываемы по Modbus. Для расчётов они сверяются с эталоном, как настройки MR6C, а любое расхождение запрещает оплачиваемые сессии.

## 3. Факты, которые меняют архитектуру

### 3.1. Unit ID 255 и WB-MGE

WB-MGE отвечает на Unit ID 255 сам: это его собственная карта регистров (модель, прошивка, uptime в 104…105), и в режиме Modbus TCP такой запрос на RS-485 не уходит. Заводской EKEPC2 с адресом 255 через `:502` поэтому недоступен. Выводы:

- первичная настройка адреса возможна только прямым USB-RS485 или через порт в режиме прозрачного моста;
- в варианте A (раздел 4) Unit ID 255 полезен: это дешёвая проверка «шлюз жив», которая не создаёт трафика на шине. Она отличает молчащее устройство от мёртвого шлюза;
- смысл пометки ETEK «255 = broadcast» неизвестен. Если на адресе 255 устройство отвечает на любой адрес, заводской EKEPC2 недопустим на общей шине даже на минуту (E-02).

### 3.2. Энергонезависимые регистры и ресурс записи

По заголовку таблицы ETEK все R/W-регистры, включая 89 и 109, хранятся в энергонезависимой памяти. evcc пишет 109 при каждом изменении тока. Для распределения тока на общем фидере это может означать тысячи записей в сутки. Ресурс памяти ETEK не публикует. Меры:

- писать только при изменении значения, предварительно сверив его чтением;
- повышать ток не чаще 30–60 с и с гистерезисом не меньше 1 А;
- снижать ток сразу, но с учётом каждой записи;
- вести счётчик записей по устройству и регистру в журнале;
- задать бюджет записей в сутки в реестре;
- ресурс запросить у ETEK и проверить на жертвенном экземпляре (E-08, E-09).

Следствие энергонезависимости: после пропадания питания EKEPC2 стартует с последним записанным лимитом. Ограничение сверху должен давать поворотный переключатель — физический потолок по кабелю и автомату. Регистр 109 лимит только снижает (проверить, E-11).

### 3.3. Карта состояний 141 зависит от прошивки

В разных источниках диапазоны разные: 0…11, 0…13 и до 19. Отображение код → состояние оформляется таблицей по версии прошивки (регистр 140). Стартовая гипотеза — карта evcc: 0 — init, 1 — A, 2 — fault, 3…4 — B, 5 — C, 19 — stop по 89. Проверить на EV-симуляторе (E-10). Прошивка не из белого списка → новые ON запрещены.

### 3.4. Регистр 89 как программный допуск

Регистр 89 принимает значения: 0 — «не задано», 1 — старт, 2 — стоп. evcc включает и выключает зарядку именно через него, и после стопа контроллер переходит в состояние 19. Это даёт:

- мягкую остановку в порядке IEC: EKEPC2 сам снимает ШИМ и размыкает P1/P2;
- второй программный допуск, независимый от MR6C.

Проверить на стенде (E-13):

- какое значение 89 после включения питания;
- не сохраняется ли 1 (тогда после пропадания питания зарядка возобновится сама — недопустимо);
- как реагирует EV на состояние 19;
- нужно ли переподключать кабель.

### 3.5. PP-резисторы в мануале 2022

Мануал 2022 сопоставляет токам сопротивления 732, 536, 432, 348 и 249 Ом для 32, 25, 20, 16 и 10 А. По IEC 61851-1 это 220 Ом для 32 А, 680 Ом для 20 А, 1,5 кОм для 13 А и 100 Ом для 63 А. Если таблица мануала верна, кабель 13 А может распознаться как 32 А. Проверить резисторами IEC по регистрам 142 и 152 (E-12). До проверки исполнение S в пилот не выпускать.

### 3.6. RCMU: автоматическое восстановление

После устранения сигнала RCMU EKEPC2 сам возобновляет зарядку. Правило исходного документа «после fault автоматического ON нет» должен обеспечивать EVcomm: по 143 ∈ {02, 03} снять разрешение MR6C и зафиксировать `FAULT` до решения оператора.

Опрос раз в 0,5–1 с может пропустить короткое срабатывание. Опция на согласование с электриком: завести сигнал FLT модуля RCMU через промежуточное реле или оптрон на вход MR6C. У MR6C есть счётчики замыканий входов; они хранятся в ОЗУ и обнуляются при сбросе питания. Прирост счётчика ловит событие между опросами.

### 3.7. Регистры 110…114: значение 3 = DIP-переключатель

Заводское значение 3 означает «по DIP-переключателю», и тогда фактическую конфигурацию по Modbus не прочитать. В эталоне требуются явные 0 или 1:

- RCMU = 1;
- RFID = 0;
- замок = 1;
- режим «розетка» по карте прошивки;
- DLB = 0, либо DLB = 1 только от трансформатора тока при 90…96 = 65535 (раздел 5.10).

Так конфигурация не зависит от положения переключателей и проверяется чтением.

### 3.8. Controller ID как идентичность

Серийного номера по Modbus у EKEPC2 нет, но есть записываемый Controller ID (118…119). При вводе в эксплуатацию туда пишется уникальный номер актива, и при каждом подключении EVcomm сверяет пару «адрес ↔ Controller ID». Так обнаруживаются перестановка контроллеров, замена без процедуры ввода и два устройства с одним адресом.

### 3.9. Инициализация около 10 с

После подачи питания EKEPC2 около 10 с выполняет самотест. Молчание в течение этого времени нормально. Признак перезагрузки (код 141 = 0? сброс 89?) установить на стенде (E-16). После любой перезагрузки выполнять полную сверку эталона.

Питание EKEPC2 должно быть подключено до Kx, иначе при отпущенном контакторе пропадает связь.

## 4. Топология шины

### 4.1. Варианты

| | A — исходный документ | **B — рекомендуется** | C — запасной |
|---|---|---|---|
| RS485-1 | MR6C + 3 × EKEPC2, 9600 8N1, Modbus TCP | MR6C один, 115 200, Modbus TCP — без изменений | MR6C один, без изменений |
| RS485-2 | счётчики, прозрачный мост | счётчики (R1: 4 шт.) + 3 × EKEPC2, 9600 8N1, прозрачный мост, Go — единственный мастер | счётчики, без изменений |
| EKEPC2 | через MGE (MGE формирует RTU) | Go формирует RTU | второй WB-MGE или отдельный порт |
| Опрос MR6C | ≥ 200 мс, ~40 % шины | 100 мс, как сейчас | 100 мс |
| Watchdog MR6C | нужен тест E-19 ×100 | не зависит от EKEPC2 конструктивно | не зависит |
| OFF MR6C при молчащем EKEPC2 | ждёт текущую транзакцию, до таймаута 250–300 мс | не ждёт | не ждёт |
| Неисправное устройство «забило» шину | MR6C теряет связь → OFF всего поста, Kx не видны | теряются счётчик и EKEPC2, MR6C и Kx видны, линии отключаются штатно | изолировано |
| Заводской адрес 255 | недоступен через `:502` | доступен через прозрачный мост (одно устройство на шине) | как B или A |
| Совместимость | README и safety-процедуры MR6C пересматриваются | счётчики только с однобайтовым адресом и драйвером Go, без «Меркурия 200»; правило 13 discovery уточняется | +1 шлюз и IP на пост |
| Программная цена | общий исполнитель на `simonvetter` | общий исполнитель + RTU-кодек поверх `internal/rtu` | минимальная |

Протоколы Modbus и «Меркурий 230» на одном порту штатно поддерживает wb-mqtt-serial. В обоих протоколах первый байт кадра — адрес slave, поэтому адреса не должны совпадать между протоколами (README wb-mqtt-serial). Правило 13 discovery-документа запрещает смешение протоколов из-за кадров «Меркурия» на адрес 00h: для Modbus-устройств это широковещательный кадр.

**Условия технической возможности варианта B.** На порту будет 5 устройств: вводной «Меркурий 234», WB-MAP12E (энергия веток, раздел 5.10) и три EKEPC2. С однофазными счётчиками было бы от 7 до 10 устройств.

1. **Протокол каждого счётчика на порту начинает кадр однобайтовым адресом 1…247**, не совпадающим с адресами EKEPC2. Подходят семейство «Меркурий 230» (его же использует 234) и Modbus RTU, на котором работает WB-MAP12E.
2. **Протокол «Меркурий 200» исключён.** Адрес там 4-байтовый: шесть последних цифр серийного номера в формате big-endian (так кадр формирует `mercury200_device.cpp` в wb-mqtt-serial). Поэтому каждый запрос и ответ начинается с 00h, и любое Modbus-устройство видит в нём широковещательный кадр. Второй байт адреса попадает в поле функции Modbus и при адресах до 999 999 лежит в 00h…0Fh — там же FC05 и FC06. Для «Меркурия 206» совместимость протоколов проверить отдельно.

   Если для учёта всё же выбран счётчик с таким протоколом, EKEPC2 уходят в вариант A или C.
3. **Другие протоколы учитываются по первому байту кадра** (README wb-mqtt-serial): МЭК 61107 начинает кадр с 01h (SOH) или 2Fh («/»), HDLC для DLMS — с 7Eh. Такие адреса Modbus на порту запрещены.
4. **Кадры на 00h запрещены** в runtime и в commissioning.
5. **Заводской EKEPC2 на порт не подключается.**
6. **Все устройства порта опрашивает Go:** `driver: wbmqtt` для таких постов закрыт.
7. **Кадры Fast Modbus (FDh) на этом порту — только в commissioning.** С WB-MAP12E на RS485-2 появляется WB-устройство. Адрес FDh лежит вне диапазона Modbus-slave, поэтому EKEPC2 и «Меркурий» его не примут, но runtime такие кадры не посылает.

Худший исход непроверенного свойства в варианте B — ошибка чтения счётчика или EVSE, которую ловят CRC и таймаут. В варианте A на кону watchdog MR6C.

### 4.2. Бюджет шины

Допущения для оценки (измерить на M1/M4):

- 9600 8N1: 1,04 мс на байт; ответ MR6C в 8N2 — 1,15 мс на байт;
- межкадровый интервал 3,65 мс дважды на транзакцию;
- накладные расходы MGE 2–4 мс на транзакцию;
- задержка ответа MR6C 1–2 мс; EKEPC2 — неизвестна, принято 5–30 мс.

| Транзакция при 9600 | Кадры | Время |
|---|---|---|
| MR6C FC01 или FC02 | 8 Б / 6 Б | 25–30 мс |
| Снимок MR6C: 3 транзакции, [snapshot.go](../internal/hardware/mr6c/snapshot.go) | | 75–90 мс |
| EKEPC2 FC03 141…152, 12 регистров | 8 Б / 29 Б | 55–80 мс |
| EKEPC2 FC06 + контрольное чтение | 8/8 Б + 8/7 Б | 65–115 мс |
| «Меркурий 234» `08 16` с ответом счётчика | ~6 Б / 15 Б | 40–80 мс |
| WB-MAP12E FC04, энергия AP трёх фаз канала (12 регистров u64) | 8 Б / 29 Б | 50–55 мс |
| WB-MAP12E FC04, Irms или P трёх фаз канала (6 регистров) | 8 Б / 17 Б | 36–41 мс |
| Однофазный счётчик, одно чтение (для сравнения) | — | 30–170 мс (оценка базовой дорожной карты, раздел 4) |

При 115 200 снимок MR6C занимает 15–30 мс.

Нагрузка счётчиков на RS485-2:

- вводной «Меркурий 234»: мощность раз в 1 с, энергия раз в 15 с — 5–9 %;
- WB-MAP12E, 6 веток:
  - ток Irms — раз в 1 с (надзор совместного режима), 2 запроса;
  - мощность — раз в 5 с;
  - энергия — раз в 15 с;
  - итого 9–11 %;
- итого 14–20 %.

С тремя однофазными счётчиками линий (R1) было бы 8–23 %, с шестью счётчиками веток — 9–31 %. Один WB-MAP12E предсказуемее: у него короткие ответы и нет медленных протоколов.

| Сценарий | MR6C | EKEPC2 | Счётчики | Итого на порту |
|---|---|---|---|---|
| A: MR6C раз в 100 мс, как сейчас | 75–90 % | — | — | **> 100 % с EKEPC2** |
| A: MR6C раз в 200 мс, 3 × EKEPC2 раз в 1 с | 38–45 % | 16–24 % | — | 54–69 % |
| **B: 3 × EKEPC2 раз в 1 с + «Меркурий 234» + WB-MAP12E** | — | 16–24 % | 14–20 % | **30–44 %** |
| B: то же, одна линия в переходе (старт или стоп) раз в 500 мс | — | 21–32 % | 14–20 % | 35–52 % |
| B: 3 × EKEPC2 раз в 500 мс + счётчики | — | 32–48 % | 14–20 % | 46–68 % |

Период опроса EKEPC2 — 1 с. На время старта или остановки конкретной линии её EKEPC2 опрашивается раз в 500 мс. Этого достаточно:

- CP, RCMU и замок EKEPC2 обрабатывает локально;
- EVcomm нужны пользовательский сценарий (plug, start) и перекрёстная проверка Kx;
- распределителю тока хватает секунды: по IEC EV отрабатывает изменение ШИМ за единицы секунд.

Ток веток для надзора совместного режима даёт WB-MAP12E: отдельно ток GB/T и ток Type 2 каждой линии. Регистр 146 EKEPC2 (ток линии по ТТ) остаётся независимым вторым источником, если ставится локальный DLB.

Предел загрузки порта в реестре — 60 %. Постоянный опрос всех EKEPC2 раз в 500 мс в худшем случае его превышает. Если измерения M4 дадут верхнюю границу, ток веток без совместного режима опрашивается раз в 5 с, а не раз в 1 с.

### 4.3. Решение

1. **Принят вариант B** при условиях раздела 4.1. Исполнитель порта транспорт-независим, поэтому A остаётся доступен без переписывания драйверов.
2. **Первое условие проверяется до закупки однофазных счётчиков R1:** их протокол должен начинать кадр однобайтовым адресом (E-26). Это решение этапа 0 базовой дорожной карты, теперь с дополнительным критерием.
3. **ADR закрепляется на гейте M4** по результатам E-18, E-20 и E-26: сосуществование протоколов, отсутствие ответов на чужие кадры.
4. **B не прошёл** → A с обязательным E-19 ×100 и пересмотром таймингов MR6C (`poll_period` ≥ 200 мс, `stale_after`, `feedback_timeout`). Не прошли оба → C.

### 4.4. Физический уровень (на согласование с электриком)

- Шина — последовательная цепочка без звезды. Терминаторы 120 Ом на двух концах: у MGE он включён по умолчанию, на дальнем конце поставить отдельно. Смещение (bias) — только у MGE.
- EKEPC2 питается от сети, а земля RS-485 у WB-MGE не изолирована от земли питания. ETEK подключает только A и B, без GND. Измерить синфазное напряжение на стенде и при необходимости поставить изолирующий повторитель.
- Контактор Kx — с зеркальным вспомогательным контактом: он единственный детектор сваривания.
- Kx однофазной линии двухполюсный и разрывает L и N. В базовой дорожной карте это исполнение 2НО+2НЗ. Для Mode 3 отключаются все токоведущие проводники — подтвердить с электриком по действующей редакции IEC 61851-1.
- Питание EKEPC2 берётся до Kx, датчик RCMU ставится после Kx на L и N.
- На линии два контактора: Kg (GB/T wallbox) и Kt (Type 2, последовательно с P1/P2 EKEPC2). Оба двухполюсные, у каждого своя НЗ-обратная связь на MR6C (раздел 5.10).

## 5. Архитектура модуля связи

### 5.1. Инварианты

1. **Один владелец на физический порт** `(gateway, rs485-N)`: одна goroutine, одно TCP-соединение. Других путей к шине нет, включая `simonvetter` из другой goroutine, отладку и второй процесс.
2. **Только типизированные операции.** Адрес 0 (broadcast) и 248…255 в API не выражаются.
3. **Все записи абсолютные.** 89 = 1/2, 109 = X, FC05 = ON/OFF — повтор безопасен. После таймаута записи — контрольное чтение, затем решение драйвера. Слепого повтора нет.
4. **Отказ устройства не рвёт порт.** TCP переподключается только при отказе транспорта.
5. **Трафик MR6C подчиняется аренде поста** (как сейчас). На EKEPC2 аренда распространяется только на записи, повышающие допуск: 89 = 1 и рост 109. Чтения, стоп и снижение тока разрешены всегда.
6. **Модуль связи не принимает решений о питании.** Он отдаёт наблюдения с качеством и исполняет команды. Правила живут в контроллере поста.

### 5.3. Контракты

```go
// Package fieldbus — владелец физического порта RS-485 за WB-MGE: одна goroutine,
// одно TCP-соединение, очередь транзакций с классами приоритета.
package fieldbus

type Class uint8

const (
	ClassSafety  Class = iota // стоп (89 = 2), снижение тока, OFF
	ClassCommand              // запись по команде и контрольное чтение
	ClassPoll                 // периодическое состояние
	ClassSlow                 // идентичность, эталон, температура
)

// Modbus — операции к одному slave. Широковещательного адреса нет.
type Modbus interface {
	ReadHolding(ctx context.Context, c Class, reg, qty uint16) ([]uint16, error)
	// WriteRegister — FC06. Таймаут возвращает ErrOutcomeUnknown: исход выяснять чтением.
	WriteRegister(ctx context.Context, c Class, reg, val uint16) error
	Health() DeviceHealth
}

type DeviceOptions struct {
	Name      string
	Timeout   time.Duration // ответ устройства; для EKEPC2 — по p99 из M1
	Gate      Gate          // весь трафик (MR6C в варианте A); nil — без аренды
	WriteGate Gate          // записи, повышающие допуск
}

// Port — физический порт. Адреса 1…247, уникальны на порту по всем протоколам.
type Port interface {
	Modbus(addr uint8, opt DeviceOptions) (Modbus, error)
	// Raw — транзакции «Меркурия» в той же очереди. Реализует rtu.Conn,
	// поэтому в mercury230.Adapter меняется только Dialer.
	Raw(addr uint8, opt DeviceOptions) (rtu.Conn, error)
	Health() PortHealth
	Run(ctx context.Context) error
}
```

```go
// Package evse — зарядная точка независимо от производителя контроллера.
package evse

type EVSE interface {
	Watch() <-chan Observation
	Latest() Observation
	// Authorize — программный допуск (EKEPC2: регистр 89) с контрольным чтением.
	Authorize(ctx context.Context, on bool) error
	// SetCurrentLimit возвращает фактически заданный ток: округление вниз,
	// ограничения кабеля и поворотного переключателя.
	SetCurrentLimit(ctx context.Context, amps float64) (applied float64, err error)
	Status() Status // online, identity, config ok, причины запрета ON
}

// PWMForCurrent — IEC 61851-1: 6…51 А соответствуют 10…85 % (I = 0,6·D).
// Округление вниз: команда никогда не превышает запрошенный ток.
func PWMForCurrent(a float64) (uint16, error) {
	if a < 6 || a > 51 {
		return 0, ErrCurrentRange
	}
	return uint16(math.Floor(a / 0.6 * 100)), nil
}
```

### 5.4. Исполнитель и планирование

- **Выбор следующей транзакции:** старший непустой класс, внутри класса — round-robin по устройствам. У каждого устройства не больше одного периодического запроса в очереди, поэтому одно устройство не вытесняет другие.
- **RS-485 не вытесняется.** Худшее ожидание класса Safety — одна текущая транзакция, не дольше её таймаута. Отсюда правило: длинные блоки дробить, если p99 блока больше 100 мс.
- **Дедлайн у каждого запроса.** Запрос с истёкшим дедлайном не отправляется, как в текущем MR6C-адаптере.
- **Проверка бюджета при загрузке реестра.** Сумма `tx_cost / period` по всем периодическим задачам порта не больше 60 %. `tx_cost` берётся из `defaults`, значения измеряются на M4.
- **Зазор между кадрами** в прозрачном мосте ≥ 3,5 символа: `rtu.Timing.FrameGap`, 5 мс при 9600.
- **Опрос EKEPC2:**
  - класс Poll: блок 141…152 одним чтением, если E-05 подтвердит чтение через «недействительные» 147…150, иначе 141…146 + 151…152;
  - класс Slow: 89 и 109 раз в 10 с, 157 раз в 30 с;
  - эталон 86…133 и идентичность 118…119, 140 — при подключении, после перезагрузки и раз в 10 мин.

### 5.5. Отказы и здоровье

| Наблюдение | Классификация | Действие |
|---|---|---|
| Исключение Modbus от устройства | устройство | ответ драйверу; соединение не трогать |
| Исключение 0x0A/0x0B от MGE (A) | устройство молчит | breaker устройства |
| Таймаут в прозрачном мосте (B) | устройство | breaker устройства |
| Таймаут в Modbus TCP (A) | неоднозначно | проба Unit ID 255 (uptime MGE) с коротким таймаутом: ответ → устройство, нет ответа → транспорт |
| CRC, мусор, чужой адрес в ответе (B) | шум шины | счётчик; одно повторное чтение для Poll и Slow |
| TCP EOF или ошибка записи | транспорт | переподключение с backoff и jitter, все устройства → `unknown`, после подключения — полная сверка |
| ≥ 2 устройств или ≥ 50 % устройств отказывают в окне 3 с при живом TCP | шина | тревога `bus_fault` вместо N тревог по устройствам |
| Uptime MGE уменьшился (A) | шлюз перезагружен | полная сверка всех устройств |

Состояния устройства:

- `online` ↔ `suspect` — 1–2 отказа подряд, опрос продолжается;
- `suspect` → `offline` — после 3 отказов подряд; раз в 5 с отправляется проба в один регистр (140);
- `offline` → `verifying` — при успешной пробе: сверка Controller ID, прошивки и эталона;
- `verifying` → `online` — после успешной сверки.

Новые ON разрешены только в `online` с `config ok`.

### 5.6. Драйвер EKEPC2

- **Идентичность:** адрес, Controller ID (118…119, порядок слов — E-24) и прошивка (140) из белого списка реестра. Любое расхождение → `config ok = false`.
- **Эталон** по аналогии с `mr6c.SafetyConfig.Expected()`:
  - 90…96 = 65535 — не мастер; 114 = 0 или 114 = 1 (DLB от ТТ), а для DLB — ещё 101…104 и 115…117 по эталону линии;
  - 110 = 1, если требуется RCMU; 111 = 0; 112 = 1, если требуется замок; 113 — «розетка» по карте прошивки;
  - 127 — полюсность линии;
  - 128…133 — токи ступеней поворотного переключателя, 151 — не выше номинала линии;
  - 86…88 — значения по умолчанию или утверждённые.

  Регистры эталона пишет только `ekepc2-bench --apply` с подтверждением, runtime только сверяет.
- **Состояние:** сырой 141 → `evse.State` по `states_v<fw>.go`. Неизвестный код → `Unknown`, новые ON запрещены, тревога.
- **Допуск (89):** по умолчанию 2 (стоп), 1 — на время сессии. Запись → контрольное чтение. Семантика — по итогам E-13. Если 89 для допуска не годится, допуск только через MR6C, а мягкая остановка недоступна (фиксируется в ADR).
- **Ток (109):**
  - `min(запрошенный, номинал линии, кабель по 142, поворотный по 151)` → `PWMForCurrent`;
  - пишется только при отличии от прочитанного 109, с учётом бюджета износа, затем контрольное чтение;
  - в B/C сверка 152 с ожидаемым значением по формуле E-11.
- **Износ:** счётчик записей по регистру в журнале. Превышение суточного бюджета → повышения тока запрещены до конца суток, снижения разрешены и ведут к тревоге.

### 5.7. Реестр

Пример для варианта B: параметры порта и EKEPC2. Раскладку поста с GB/T и Type 2 на каждой линии (выходы K1–K6, ветки, совместный режим) задаёт раздел 5.10.

```yaml
posts:
  - id: bench01
    gateway: 192.168.1.50:502      # RS485-1: только MR6C, 115 200 — без изменений
    mr6c_address: 1
    meter:
      driver: mercury230           # обязателен при EKEPC2 на RS485-2: Go — единственный мастер
      gateway: 192.168.1.50:503
      address: 145
    # R1: однофазные счётчики L1–L3 на том же порту — секция реестра этапа 2 базовой карты;
    # протокол с однобайтовым адресом, адреса не пересекаются с EKEPC2
    evse_port:                     # тот же физический порт, что у meter
      transport: bridge            # bridge (вариант B) | modbus_tcp (вариант A)
      uart: 9600-8N1               # декларация: MGE настраивается отдельно, сверка по ответам
      max_utilization: 0.6
      poll_period: 1s
      transition_poll_period: 500ms  # линия в старте или остановке
      lost_grace: 3s               # потеря связи во время заряда → MR6C OFF
    evse:
      L1: { driver: ekepc2, address: 20, controller_id: 100120, firmware: [1002], max_current_a: 32, phases: 1 }
      L2: { driver: ekepc2, address: 21, controller_id: 100121, firmware: [1002], max_current_a: 32, phases: 1 }
      L3: { driver: ekepc2, address: 22, controller_id: 100122, firmware: [1002], max_current_a: 32, phases: 1 }
```

Проверка отклоняет:

- адреса вне 1…247;
- совпадение адресов на физическом порту, включая адреса всех счётчиков;
- счётчик с протоколом «Меркурий 200» или любым другим, чей первый байт кадра не однобайтовый адрес, на порту с EKEPC2;
- адреса Modbus, совпадающие с префиксами кадров протоколов порта (01h, 2Fh, 7Eh);
- `driver: wbmqtt` у счётчика поста с EKEPC2 на его порту;
- `evse` на линии 3P;
- EVSE на линии без НЗ-обратной связи;
- `max_current_a` выше `limits.evse_max_a`;
- превышение `max_utilization` по расчёту бюджета;
- прошивку вне белого списка.

### 5.8. Интеграция с контроллером поста

Без этого модуль связи бесполезен, поэтому это входит в карту (M6). Для линии с `evse` автомат расширяется:

- **`ARMED`** — разрешение MR6C подтверждено по coil и real state, Kx может быть отпущен. НЗ-подтверждение включения не требуется, `feedback_timeout` к включению не применяется.
- **Перекрёстные проверки** с окном `T_x = 2 × период опроса EVSE + время срабатывания Kx`:
  - Kx притянут, а EVSE не в C дольше `T_x` → `FAULT` (сваривание Kx или залипание P1/P2);
  - EVSE в C при разрешении MR6C, а Kx отпущен дольше `T_x` → `FAULT` (цепь катушки, MR6C или Kx);
  - разрешение MR6C снято, а Kx притянут → существующая логика `FAULT`.
- **Старт:**
  1. EVSE `online`, `config ok`;
  2. RCMU 01, замок допустим, состояние B;
  3. ток (109) задан и сверен;
  4. MR6C ON → `ARMED`;
  5. 89 = 1;
  6. переход в C и притяжение Kx → сессия `active` и снимок энергии.

  EKEPC2 замыкает силовую цепь последним, в порядке IEC.
- **Штатный стоп:**
  1. 89 = 2;
  2. ожидание выхода из C и отпускания Kx, `T_soft` подбирается на стенде, ориентир 3–5 с;
  3. MR6C OFF;
  4. подтверждение по НЗ;
  5. снимок энергии.

  Не уложились в `T_soft` → MR6C OFF с пометкой «hard stop».
- **Авария** (EVSE fault, RCMU 02/03, отказ замка): MR6C OFF сразу, параллельно 89 = 2 в классе Safety. `FAULT` фиксируется до решения оператора независимо от того, что EKEPC2 возобновит заряд сам.
- **Потеря связи с EKEPC2 во время заряда** (устройство `offline` или порт в `bus_fault`):
  - по истечении `lost_grace` = 3 с — MR6C OFF, Kx разрывает L и N;
  - сессия закрывается с причиной `hard stop: evse comm lost`, конечный снимок энергии берётся со счётчика линии;
  - новые ON запрещены до восстановления связи и полной сверки EKEPC2 (Controller ID, прошивка, эталон).

  Мягкая остановка без связи невозможна: регистр 89 не записать. Разрыв под нагрузкой здесь допустим как редкое аварийное событие. Локальная защита EKEPC2 работает и без связи.

### 5.10. Линия с двумя разъёмами: GB/T и Type 2

#### Схема линии

```text
ввод поста ─ автомат линии Ln 32 А ─ ТТ (DLB EKEPC2, опция) ─┬─ Kg ─ ТТ WB-MAP12E Ch1 Ln ─ штатный wallbox GB/T (Geely/BYD)
                                                             └─ Kt ─ ТТ WB-MAP12E Ch2 Ln ─ RCMU ─ Type 2 (EKEPC2)
катушка Kg: выход MR6C
катушка Kt: выход MR6C ── последовательно ── P1/P2 EKEPC2
WB-MAP12E: входы напряжения L1, L2, L3 — от ввода поста до автоматов линий; питание интерфейсной части 24 В — от Vout WB-MGE
```

| Токовый вход WB-MAP12E | Фаза напряжения | Ветка |
|---|---|---|
| Ch1 L1, Ch1 L2, Ch1 L3 | L1, L2, L3 (заводская привязка) | GB/T линий L1, L2, L3 |
| Ch2 L1, Ch2 L2, Ch2 L3 | L1, L2, L3 | Type 2 линий L1, L2, L3 |
| Ch3, Ch4 | — | резерв: сумма линий для сверки или ввод, только технический учёт |

Линия Ln питается от фазы Ln, поэтому заводская привязка «токовый вход Lx → фаза Lx» совпадает со схемой, и перепривязка фаз (`Actual Phase Lx`) не нужна.

| Выход и вход MR6C | L1 | L2 | L3 |
|---|---|---|---|
| Kg (GB/T) | K1 / вход 1 | K2 / вход 2 | K3 / вход 3 |
| Kt (Type 2) | K4 / вход 4 | K5 / вход 5 | K6 / вход 6 |

Раскладка K1–K3 сохраняет текущее соответствие «выход → линия» и НЗ-обратную связь на входах 1…3.

- Вход 0 свободен. Опция: параллельно завести FLT трёх RCMU через промежуточные реле. Счётчик замыканий входа 0 тогда ловит любое срабатывание между опросами, а какая линия сработала, показывает регистр 143.
- Линия 3P (K4) и режим `1x3` на таком посту недоступны. Если они нужны, требуется второй MR6C, а значит и новая раскладка реестра.

#### Правила ветки GB/T

Штатный wallbox — чёрный ящик, как EVSE в базовой архитектуре. EVcomm не видит CP и не задаёт ток, только подаёт питание через Kg и измеряет потребление счётчиком. Автомат ветки — существующий автомат линии: ON и OFF подтверждаются НЗ Kg за `feedback_timeout`.

#### Правила ветки Type 2

Автомат EVSE-линии раздела 5.8 на Kt, как описано выше.

#### Взаимодействие веток одной линии

Правило асимметричное, приоритет у GB/T:

| Состояние линии | Старт GB/T | Старт Type 2 |
|---|---|---|
| свободна | разрешён | разрешён, лимит `min(line_max_a, кабель по PP, поворотный)` |
| идёт GB/T | — | разрешён в совместном режиме, если запас ≥ 6 А (ниже) |
| идёт Type 2 | **запрещён** до конца сессии Type 2, Kg подтверждённо OFF | — |
| совместный режим | — | — |

Причина асимметрии: ток wallbox не ограничить. Включить GB/T при работающем Type 2 — значит допустить ток до 32 + лимит Type 2 на автомат линии 32 А.

**Совместный режим** — Type 2 подключается, пока идёт GB/T.

1. **Условие входа.** GB/T в установившемся режиме не меньше `share_settle` (ориентир 60 с). Пиковый ток GB/T за это окно по Irms канала Ch1 WB-MAP12E — `I_g`. Тогда лимит Type 2 = `floor(line_max_a − I_g − share_margin_a)`. Для гибрида на 16 А и линии на 32 А это 16 А. Если лимит меньше 6 А, вход в совместный режим отклоняется с причиной «недостаточно тока линии».
2. **Лимит в MVP фиксирован на всю сессию Type 2:** одна запись 109 на старт. Это минимум износа памяти и никаких колебаний. После окончания GB/T лимит Type 2 не поднимается, чтобы при повторном потреблении wallbox (догрев, возобновление) не было перегрузки.
3. **Надзор.** Ток линии больше `line_max_a + share_tolerance_a` дольше `share_trip_after` (ориентир 3 с) → Type 2 останавливается мягко (89 = 2). Если ток не снизился за `T_soft` → Kt OFF. GB/T как основная ветка не отключается. Ток линии — сумма Irms веток Ch1 и Ch2 WB-MAP12E: опрос раз в 1 с, 2 запроса на все линии. При установленном ТТ DLB регистр 146 EKEPC2 служит вторым независимым источником. Их расхождение больше 2 А — тревога.
4. **Локальный DLB EKEPC2 — следующий шаг после MVP.** ТТ ставится на линию до разветвления, 114 = 1, 96 = 65535, 102 = `line_max_a`, коэффициент ТТ — в 103. Тогда EKEPC2 сам ограничивает Type 2 по полному току линии быстрее и без сети, и регистр 109 не переписывается. Включается только после E-27 (поведение ниже 6 А, время реакции) и E-17 в этом режиме.

   С рабочим DLB правило «Type 2 первым → GB/T запрещён» можно ослабить: GB/T стартует, EKEPC2 снижает или приостанавливает Type 2. Это отдельное решение политики.

#### Учёт энергии

Правило базовой дорожной карты (раздел 11 исследования): каждая оплачиваемая сессия — разность показаний своего учётного регистра, который не меняет другая нагрузка. В совместном режиме на линии две сессии разных ЛС, поэтому учёт ведётся по ветке.

| Вариант | Приборы | Совместный режим | Шина RS485-2 |
|---|---|---|---|
| U1 — счётчик на линию (R1) | 3 однофазных + вводной | только для одного ЛС | 7 устройств, 24–47 % |
| U2 — однофазный счётчик на ветку | 6 однофазных + вводной | для разных ЛС | 10 устройств, 25–55 % |
| **U2-MAP — канал WB-MAP12E на ветку (принят)** | 1 WB-MAP12E + 6 ТТ + вводной | для разных ЛС | 5 устройств, 30–44 % |
| U3 — счётчик линии + Type 2, GB/T = разность | 6 однофазных + вводной | нет | разность не является показанием средства измерения — для расчётов непригоден |

**Почему WB-MAP12E, а не другой прибор линейки:**

- из многоканальных WB-MAP в Госреестр СИ внесён WB-MAP12E (79082-20);
- для WB-MAP6S производитель прямо пишет, что он в реестр не внесён, и для применения с поверкой советует WB-MAP12E в режиме 12 однофазных каналов;
- WB-MAP3ET не внесён;
- WB-MAP3E внесён, но у него 3 канала, а нужно 6.

Характеристики WB-MAP12E:

- класс точности 0.5S по активной энергии;
- энергия AP по каждому токовому входу — регистр u64 с шагом 10⁻⁵ кВт·ч (0,01 Вт·ч);
- накопленная энергия сохраняется при отключении питания;
- Modbus RTU, по умолчанию 9600 8N2 (на порту задать 8N1 или положиться на терпимость WB-устройств к стоп-битам).

**Что остаётся за метрологом и юристом.** Это то же решение этапа 0 базовой дорожной карты, теперь для WB-MAP12E:

1. **Назначение прибора.** Производитель указывает энергоменеджмент и технологический учёт в МКД. Ранее техподдержка Wiren Board писала, что WB-MAP для коммерческого учёта не подходят ([исследование счётчиков](rs485-phase-energy-meter-research.md)). Внесение в реестр само по себе не делает прибор пригодным для расчётов с жильцами.
2. **Описание типа.** Нормирует ли оно энергию по каждому токовому входу, то есть по каналу-фазе, и включает ли в измерительный канал используемые разъёмные ТТ.
3. **Поверка.** Нужна поверка прибора вместе с ТТ и известен межповерочный интервал.

Если метролог откажет, запасной путь — U2 на однофазных поверенных счётчиках с однобайтовым адресом: 10 устройств на порту, загрузка по оценке 25–55 %. Архитектура модуля при этом не меняется, меняется только драйвер счётчика.

**Целостность учёта.** В отличие от опломбированного счётчика, у WB-MAP12E по Modbus записываемы:

- коэффициенты ТТ (`Turns Lx`, `Phi Lx`);
- инверсия ТТ;
- привязка фаз (`Actual Phase Lx`).

Ошибка в привязке фаз, по словам производителя, даёт неверные, но похожие на правду значения. Ошибка в коэффициентах ТТ проявляется так же. Поэтому:

- эталон этих регистров для всех шести используемых входов фиксируется при вводе в эксплуатацию. EVcomm сверяет его при подключении, после перезагрузки и раз в 10 мин, как эталон MR6C. Расхождение → оплачиваемые сессии на посту запрещены, тревога, запись в журнал;
- серийный номер и прошивка WB-MAP12E (стандартная карта WB) сверяются с реестром при каждом подключении, как серийный номер «Меркурия»;
- драйвер WB-MAP12E в runtime не выполняет ни одной записи. Эталон пишет только процедура ввода, с подтверждением;
- уменьшение энергии канала или скачок сверх `line_max_a × 230 В × Δt` дают качество `disputed`, как в модуле «Меркурий 230»;
- единственный мастер порта — Go: прозрачный мост допускает одного клиента, а сетевой доступ к 503 разрешён только Go-хосту. Посторонний клиент не может переписать ТТ.

Режим Type 2 первым, с запретом GB/T, даёт одну сессию на линии и учитывается тем же каналом ветки.

#### Реестр

```yaml
posts:
  - id: bench01
    layout: gbt_type2_3x1          # K1–K3 — GB/T, K4–K6 — Type 2; 1x3 и 3P недоступны
    metering: per_branch           # per_branch (U2) | per_line (U1)
    branch_meter:                  # один прибор на все ветки поста, порт RS485-2
      driver: wbmap12e
      address: 40
      serial: "..."                # из паспорта; сверяется при подключении
      verification_until: 2032-09-01
      ct:                          # эталон, записан при вводе; runtime только сверяет
        ch1: { l1: { turns: ..., phi: ... }, l2: {...}, l3: {...} }
        ch2: { l1: {...}, l2: {...}, l3: {...} }
    lines:
      L1:
        line_max_a: 32
        share: { settle: 60s, margin_a: 0, tolerance_a: 2, trip_after: 3s, min_a: 6 }
        gbt:   { output: 1, feedback: 1, meter: { channel: 1, input: l1 } }
        type2: { output: 4, feedback: 4, meter: { channel: 2, input: l1 },
                 evse: { driver: ekepc2, address: 20, controller_id: 100120, firmware: [1002], dlb: off } }
```

Проверка реестра:

- в `gbt_type2_3x1` каждый выход и вход MR6C используется ровно один раз;
- каждый токовый вход WB-MAP12E назначен не более чем одной ветке, а фаза входа совпадает с фазой линии;
- у `branch_meter` есть `serial`, `verification_until` и полный эталон `ct` для всех назначенных входов;
- адрес WB-MAP12E уникален на RS485-2 среди адресов «Меркурия» и EKEPC2;
- `dlb: ct` требует 90…96 = 65535 в эталоне;
- при `metering: per_line` совместный режим разрешён только для сессий одного ЛС (правило в политике допуска).

Затрагивается существующий код:

- `registry.Post.Lines()` сейчас даёт фиксированную раскладку L1–L3 и 3P, её нужно сделать зависимой от `layout`;
- `policy.CheckEnable`: вместо групповой блокировки `3x1`/`1x3` — правила веток и тока линии;
- `domain.LineID`: у ветки свой идентификатор, например `L1.gbt` и `L1.t2`, со ссылкой PWA на ветку.

## 6. Дорожная карта

Оценки — рабочие дни одного разработчика, без поставки оборудования и электрической экспертизы.

### M0 — Решения и заморозка (2–3 дня)

- ADR «топология EKEPC2»: кандидат B, запасные A и C; закрывается на M4.
- Закупка: не меньше трёх EKEPC2-S одной партии и один жертвенный экземпляр. Зафиксировать регистр 140, маркировку, положения DIP и поворотного переключателя.
- Учёт веток:
  - WB-MAP12E с шестью ТТ, заказать с услугой «Настройка счётчика» (параметры ТТ записаны в прибор, ТТ промаркированы);
  - вопросы метрологу и юристу — раздел 5.10;
  - запасной путь — однофазные поверенные счётчики с однобайтовым адресом, «Меркурий 200» не подходит.
- Адресный план RS485-2 на 5 устройств, например: «Меркурий 234» — 145; WB-MAP12E — 40; EKEPC2 L1–L3 — 20…22.
- Состав линии (раздел 5.10): GB/T через штатный wallbox, Type 2 через EKEPC2. У wallbox выяснить:
  - режим «plug and charge», без карты и приложения;
  - поведение после подачи питания;
  - номинальный ток.
- Схема на согласование: Kg и Kt на линию, P1/P2 последовательно с Kt, питание EKEPC2 до Kt, двухполюсные контакторы (L+N) с зеркальным контактом, опционально ТТ линии для DLB и FLT RCMU → вход 0 MR6C.
- Запрос в ETEK:
  - карта 141 для прошивки;
  - ресурс записи;
  - семантика 89 и адреса 255;
  - таблица PP;
  - поведение после RCMU-fault.

**Гейт:** BOM и прошивка записаны, вопросы ETEK отправлены.

### M1 — Один EKEPC2 на стенде (4–5 дней)

- `cmd/ekepc2-bench` v0: `identity`, `status`, `watch`, `raw-read`, `raw-write --apply`, `latency -n`. Работает напрямую через `simonvetter` (`rtu://` для USB-RS485, `rtuovertcp://` для прозрачного моста), без общего исполнителя.
- Проверки E-01…E-17 (раздел 7).
- Результат: `registers_v<fw>.go` и `states_v<fw>.go`, таблица задержек, факты о сохранении и отчёт в `docs/`.

**Гейт:** карта подтверждена на двух экземплярах. Известны скорость, p99, поведение адреса 255, семантика 89, 109 и 152, результат PP по IEC. Отрицательный результат E-12 или E-17 — стоп проекта до ответа ETEK.

### M2 — Исполнитель порта на симуляторах (6–8 дней, параллельно с M1)

- `internal/rtu`: предикат длины кадра. Существующий контракт `Transact` сохраняется.
- `internal/fieldbus`: очередь, классы, дедлайны, breaker, классификация отказов, `Raw()`, метрики, оба транспорта. Этот же исполнитель закрывает пункт этапа 2 базовой дорожной карты «адаптер RS485-2 для нескольких счётчиков (R1)».
- `internal/sim/bridge.go`: один TCP-сервер прозрачного моста с диспетчеризацией по адресу и инъекцией отказов: тишина, мусор, задержка, болтовня. Основной профиль — «Меркурий 234», WB-MAP12E и 3 EKEPC2: существующий симулятор «Меркурия» плюс новые WB-MAP12E и EKEPC2. Запасной профиль для U2 на однофазных счётчиках — 7 счётчиков и 3 EKEPC2.
- Тесты:
  - `-race` при 16 одновременных вызывающих;
  - тишина одного устройства не рвёт TCP и не задерживает Safety дольше одной транзакции;
  - болтовня → `bus_fault`;
  - таймаут записи → контрольное чтение, без слепого повтора;
  - 100 портов × 4 устройства на Pi 5 — CPU и память.

**Гейт:** тесты зелёные, 24 ч прогона на симуляторе без роста памяти и goroutine.

### M3 — Драйверы EKEPC2 и WB-MAP12E, перевод счётчика (6–9 дней)

- `internal/evse`, `internal/hardware/ekepc2` по разделу 5.6. `internal/sim/ekepc2` строится по фактам M1.
- `mercury230.Adapter` получает `Dialer` поверх `Port.Raw()`. Протокол и логика счётчика не меняются, существующие тесты проходят.
- `internal/hardware/wbmap12e` (раздел 5.10):
  - identity (serial, fw) и эталон ТТ;
  - Irms раз в 1 с, P раз в 5 с, энергия раз в 15 с и по событию;
  - снимок энергии ветки с сырыми регистрами и проверкой монотонности;
  - реализация `measurements.Source` на ветку.

  Симулятор WB-MAP12E — в `internal/sim/bridge.go`.
- Unit-тесты: конвертер тока, включая округление вниз и границы 6 и 51 А; карта 141; эталон; бюджет износа.

**Гейт:** сценарии симулятора совпадают с записанными на M1 кадрами стенда.

### M4 — Общая шина на WB-MGE: 3 EKEPC2, «Меркурий 234», WB-MAP12E (5–6 дней)

- Вариант B: RS485-2 в режиме прозрачного моста — вводной «Меркурий 234», WB-MAP12E с шестью ТТ и три EKEPC2. MR6C на RS485-1 без изменений.
- Проверки:
  - E-18, E-20, E-22…E-24, E-26, E-30;
  - 10 000+ смешанных транзакций;
  - утилизация и p99 полного цикла, в том числе с линией в переходе (500 мс);
  - снятие питания с одного устройства;
  - перестановка адресов.
- Если B не прошёл E-18, E-20 или E-26 — тот же набор для A плюс E-19 ×100 и E-21.

**Гейт:** ADR закрыт с данными, `tx_cost` внесены в `defaults`, загрузка ≤ 60 % для 3 EKEPC2, «Меркурия 234» и WB-MAP12E.

### M5 — Ввод в эксплуатацию (4–5 дней)

- `ekepc2-bench commission` на изолированной шине с одним устройством:
  1. адрес;
  2. Controller ID;
  3. эталон;
  4. снятие и подача питания;
  5. повторная сверка;
  6. печать бирки.
- WB-MAP12E:
  1. адрес и UART;
  2. чтение serial и прошивки;
  3. сверка параметров ТТ с наклейками, если прибор заказан с услугой «Настройка счётчика», иначе запись с подтверждением;
  4. снимок эталона ТТ и привязки фаз в реестр.
- Проверка соответствия «ветка ↔ разъём ↔ адрес EKEPC2 ↔ выход MR6C ↔ Kx ↔ вход WB-MAP12E». Нагрузка или EV-симулятор подключается по очереди в каждую из шести веток. Ожидается:
  - притягивается ожидаемый Kx;
  - ток появляется ровно на одном ожидаемом входе WB-MAP12E;
  - для Type 2 состояние меняет ровно один адрес EKEPC2.
- Порт переводится в режим commissioning по правилам раздела 5 discovery-документа.

**Гейт:** все устройства поста введены по процедуре без ручной правки регистров. Обнаруживаются при подключении:

- перестановка двух EKEPC2;
- перестановка ТТ между ветками;
- изменение параметра ТТ.

### M6 — Интеграция с контроллером поста (9–12 дней)

- Автомат EVSE-ветки по разделу 5.8, фиксированный лимит 16/32 А, реестр и валидация, метрики, журнал записей.
- Раскладка `gbt_type2_3x1` (раздел 5.10): ветки линии, асимметричная блокировка GB/T ↔ Type 2, совместный режим с фиксированным лимитом и надзором за током линии, учёт сессий по каналам WB-MAP12E (U2-MAP) в политике допуска.
- Сценарии на симуляторе и на стенде:
  - C→B→C не даёт `FAULT`;
  - RCMU-fault фиксирует `FAULT` даже после самовосстановления EKEPC2;
  - сваривание Kx обнаруживается;
  - мягкая остановка укладывается в `T_soft`;
  - потеря связи с EKEPC2 во время заряда → MR6C OFF через 3 с, L и N разорваны, сессия закрыта с конечным снимком;
  - Type 2 первым → старт GB/T отклоняется, Kg остаётся OFF;
  - GB/T с гибридом 16 А + Type 2 → лимит Type 2 16 А, ток линии ≤ 32 А (E-29);
  - рост тока GB/T в совместном режиме → мягкая остановка Type 2 за `share_trip_after` + `T_soft`, GB/T продолжает;
  - E-25, E-28 на реальных Geely и BYD.

**Гейт:** чек-лист раздела 16 исходного документа на стенде. В варианте B пункты про общую с MR6C шину заменяются на E-18 и E-20.

### M7 — Стойкость (5–10 календарных дней)

- 72 ч смешанного трафика.
- Случайное снятие питания с MGE, EKEPC2, «Меркурия» и MR6C.
- Обрыв и замыкание линии безопасным способом, Ethernet flap, перезапуск Pi.
- Счётчики записей в энергонезависимую память — в пределах бюджета.

**Гейт:** нет ложных `FAULT`, нет уменьшений энергии в снимках, нет превышения бюджета записей. Передача в пилот (этап T9 исходного документа).

### M8 — Динамическое распределение тока (после пилота)

- Распределитель по фидеру: сначала снизить ток одному EKEPC2 и подтвердить (чтение 109, в C — 152 и ток по счётчику), только потом повысить другому.
- EKEPC2 без связи считается работающим на максимуме `min(поворотный, последний 109)`. Если сумма превышает лимит фидера — снять разрешение MR6C.
- Нужна статистика износа с пилота.

## 8. Решения

### 8.1. Приняты 26.09.2026

| Вопрос | Решение | Следствие |
|---|---|---|
| EKEPC2 на пост | по одному на однофазную линию L1–L3, N = 3; EV — однофазные Geely и BYD | бюджет раздела 4.2 считается для 3 EKEPC2; линия 3P вне объёма |
| RS485-2 для счётчиков и EKEPC2 | да, если технически возможно | возможно при условиях раздела 4.1: протоколы с однобайтовым адресом, без «Меркурия 200», без кадров 00h; `driver: wbmqtt` для таких постов закрыт |
| Потеря связи с EKEPC2 во время заряда | отключить линию контактором по фазе и нейтрали | MR6C OFF через `lost_grace` = 3 с; Kx двухполюсный; новые ON — только после сверки (раздел 5.8) |
| Разъёмы линии | основной GB/T от штатного wallbox Geely или BYD, вспомогательный Type 2 с EKEPC2; совместная работа при остатке тока (гибрид 16 А); Type 2 первым → GB/T неактивен | раздел 5.10: Kg и Kt на линию, все 6 выходов MR6C, `1x3` недоступен; асимметричная блокировка; совместный режим с фиксированным лимитом и надзором |
| Граница блокировки | в пределах одной линии | другие линии поста не блокируются: у них свои фазы и автоматы |
| Учёт совместного режима | сессии разных ЛС одновременно; вместо однофазных счётчиков — прибор линейки WB-MAP | U2-MAP: один WB-MAP12E на пост, канал 1 — GB/T, канал 2 — Type 2; эталон ТТ сверяется; на RS485-2 пять устройств (раздел 5.10) |

### 8.2. Открыты

1. **Метрологическое подтверждение WB-MAP12E для расчётов с жильцами** — раздел 5.10: назначение прибора, описание типа 79082-20 по каждому входу с ТТ, поверка. До ответа метролога оплачиваемые сессии на WB-MAP12E в пилот не выпускать. Запасной путь — однофазные поверенные счётчики на ветку.
2. **Регистр 89 как программный допуск.** Решение после E-13. Без него остановка Type 2 всегда жёсткая, через MR6C.
3. **ТТ линии для локального DLB и сигнал FLT RCMU на вход 0 MR6C.** Согласовать с электриком. Без ТТ DLB совместный режим работает на фиксированном лимите с надзором по WB-MAP12E.
4. **Встроенные измерения EKEPC2** (147…149) недействительны. Энергия сессии берётся только с канала WB-MAP12E её ветки — подтвердите, что другого не ожидается.
