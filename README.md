# EVcomm — управление питанием линий EVSE

Go-сервис для Raspberry Pi 5. Он разрешает и снимает питание линий EVSE на постах с WB-MGE v.3 и WB-MR6C v.3. Архитектура описана в [дорожной карте](docs/roadmap_evse_line_control_go_2026-09-25.md) и [исследовании](docs/research_wb_mqtt_serial_go_integration_2026-09-25.md).

Сейчас реализован вертикальный прототип этапа 1: **Go → WB-MGE (Modbus TCP, 502) → MR6C → контактор с НЗ**, с арендой и watchdog на безопасном режиме MR6C.

## Структура

```text
cmd/line-controller          сервис: все посты из реестра, OFF всех линий при остановке (API — этап 4)
cmd/mr6c-bench               стенд: ручное ON/OFF, серии с p50/p99, проверка watchdog
cmd/mr6c-sim                 симулятор MR6C за WB-MGE (Modbus TCP)
cmd/gen-serial-config        генератор wb-mqtt-serial.conf (этап 4, заглушка)
internal/domain              линии, режимы, состояния, команды, наблюдения
internal/registry            реестр постов (YAML), значения по умолчанию, проверка
internal/controller          автомат состояний поста, подтверждение, сверка, аренда
internal/policy              режимы 3x1/1x3, блокировка групп, бюджет фаз
internal/hardware/mr6c       карта регистров, опрос, FC05, эталон настроек
internal/supervision         аренда (lease)
internal/sim                 симулятор MR6C: контакторы, НЗ, безопасный режим, неисправности
internal/measurements/wbmqtt счётчики через wb-mqtt-serial (заглушка)
internal/store, internal/api журнал и API (заглушки)
configs/bench.yaml           реестр стенда
```

## Как это работает

- **Аренда.** Цикл управления поста на каждом такте продлевает `lease` на `lease_ttl`. Адаптер MR6C выполняет чтения и записи, только пока аренда действует. Если зависает цикл, адаптер или весь процесс, трафик к модулю прекращается. Через `poll_timeout_s` MR6C переводит выходы в OFF.
- **Подтверждение.** Сначала FC05 на coil Kn. Затем сразу контрольное чтение выхода (FC01) и фактического состояния (FC02 96+). ON или OFF подтверждается только НЗ-входом контактора. Команда получает `confirmed` лишь после этого. Задержки каждого шага записываются в результат.
- **Сверка.** Приложение стартует с неизвестным состоянием линий и без автоматического ON. Линии, найденные включёнными, отключаются. Если цикл простоял дольше аренды или свежих данных нет дольше `stale_after`, включения запрещаются. Линии, которые были под напряжением, после восстановления связи уходят в `FAULT` до `reset` оператором.
- **Эталон MR6C** сверяется при каждом подключении. При расхождении включения запрещены. В эталон входят:
  - регистры 5, 6, 8, 19;
  - режим «управление отключено» (3) для входов 0…6;
  - 930…951 для всех шести выходов.
- **Блокировка.** В режиме `3x1` разрешены только L1–L3, в режиме `1x3` — только 3P. Линии другой группы должны быть подтверждённо OFF. Сверх того проверяется бюджет фаз (32 А на линию, лимит фазы 60 А). Смена режима допускается только при всех линиях OFF и после `mode_switch_pause`.
- **Идемпотентность.** Повторная команда с тем же `command_id` возвращает сохранённый результат. Новая команда по линии вытесняет незавершённую, поэтому устаревшая ON не переигрывает OFF.

## Быстрый старт на симуляторе

```bash
make test
```

```bash
go run ./cmd/mr6c-sim
```

```bash
go run ./cmd/mr6c-bench -registry configs/bench.yaml
```

Симулятор запускается с настройками по эталону. Флаг `-factory` даёт заводские настройки: стенд не разрешит включение, пока не выполнена `apply-safety`. Флаг `-stuck 1` имитирует контактор K1, который не срабатывает.

## Реальный стенд

1. **WB-MGE v.3.** Порт RS485-1 перевести в режим Modbus TCP на 115 200 бит/с (TCP 502). Кэширующий мультимастер и сниффер выключить. К порту 502 должен иметь доступ только хост с Go: любой другой клиент сбрасывает таймер безопасного режима.
2. **MR6C.** Задать адрес и скорость 115 200. Прошивка нужна ≥ 1.24.0 ради фактического состояния выходов, иначе `real_state: false`. НЗ-контакты K1…K4 подключить к входам 1…4. Входы — «сухой контакт», сетевое напряжение на них не подавать.
3. **Реестр.** В `configs/bench.yaml` указать `gateway: <IP шлюза>:502` и `mr6c_address`. Если модуль отвечает ошибкой на сплошное чтение входов 0…7, выставить `input_read: split`.
4. Запустить `mr6c-bench`, выполнить `status` и `verify`. Если эталон расходится, выполнить `apply-safety`: команда записывает регистры модуля и требует ввести `yes`.

Сценарии этапа 1 (раздел 9.6 исследования):

| Проверка | Команда |
|---|---|
| ON/OFF с подтверждением по НЗ | `on L1`, `off L1`, `status` |
| Задержки p50/p99, 1000 циклов | `cycle L1 1000`. Между переключениями выдерживается `min_switch_interval`; для серии его можно уменьшить в реестре, если это допустимо для контактора |
| Зависание цикла при живом адаптере | `watchdog L1` или `hang 5s` |
| Остановка процесса | `on L1`, затем `kill -STOP <pid>` (PID выводится при старте), через 5 с `kill -CONT <pid>`, затем `status`: L1 должна быть в `FAULT … outputs found released` |
| Неисправность обратной связи | снять провод НЗ: линия уходит в `FAULT`, включение запрещено |
| Эталон не совпадает | изменить регистр 8 на модуле, выполнить `verify`: включения запрещены |

Сборка для Pi 5 (linux/arm64, без cgo): `make pi`, бинарники появятся в `bin/linux-arm64/`.

## Ограничения прототипа

- Время подтверждения по НЗ кратно периоду опроса (`poll_period`, 100 мс). Для точного замера времени срабатывания контактора нужно уменьшить период или использовать осциллограф или анализатор.
- Не реализованы (этапы 1–4): чтение Меркурий 234 через wb-mqtt-serial (порт 503), сессии и снимки энергии, неизменяемый журнал, API, генератор конфига wb-mqtt-serial, диагностика по току счётчика.
- Численные значения `lease_ttl`, `poll_timeout_s` и `feedback_timeout` — исходные предложения. Утверждаются на этапе 0.
